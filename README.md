# esmc-frozen-probe

用 **ESMC（ESM Cambrian）冻结编码器 + 轻量头部**做蛋白性质预测的可复现流水线。
两条独立任务线：

| 线 | 任务 | 数据 | 主指标 |
|---|---|---|---|
| `solubility/` | eSOL 溶解度回归 | 3,157 条 E. coli 蛋白 | Spearman |
| `ddg/` | 热稳定性 ΔΔG 回归 | 529,740 条单点突变 / 298 蛋白 | Spearman |

> **本仓库的主体是写给"下一个 agent"的。** 口径写成 `PROTOCOL.md`（含理由），
> 静默失败写成 `PITFALLS.md`，结果写成可断言的快照 `*/expected/`。
> 目标是：换一台机器能跑出**同一批数字**；如果不一致，能**定位到哪一步**不一致。

---

## 先说人话

上面那句说的是**写法**，不是拒客 —— 这一段专门给**人**读。

**它不是一个刷分项目，是一次可信度审计。** 做法是：**不训练大模型**，
把一个**冻住的**蛋白语言模型（ESMC）当特征提取器，只在上面接一个很小的头部；
然后不去问"分数能刷多高"，而是问三个更要紧的问题：

1. **分数里有多少是虚的？** 数据划分没做同源隔离的话，测试集里会混进近亲序列，
   分数自然虚高。我们把这件事**量出来**，并用干净划分给出真实水平。
2. **加的东西真的有用吗？** 一律用**配对检验**判，不看两个数字谁大。
   结果和直觉相反：数据量小的时候，"把线性头换成更强的 MLP"并没有可测的收益。
3. **换更大的编码器值不值？** 两条线的**答案相反** —— 一条已经饱和，一条还没有；
   而差别来自**数据量**、不来自编码器本身。

**第 3 条是这个仓库最值得看的地方**：同一套方法、同一套判据，在两个任务上得出相反结论，
合起来看才能逼出一句结论 —— **卡住你的是数据量，不是模型大小**。这类对照通常散落在互不引用的
论文里，很少有机会放在一起看。而且**每个数字都能在本机重跑出来**，不是只给你一个结论。

**还有一类平时看不到的东西**：`PITFALLS.md` 里那 **14 条静默失败** ——
**不报错、但结果错**。这类坑一般只留在作者脑子里、不会写进论文；想少走弯路的话，
它可能比结论本身更值钱。

**动手前先知道一件事**：数据集与模型权重**都不在本仓库**（许可与体积原因，6B 权重单个就
23.66 GiB）。克隆下来是几 MB 的代码与文档，跑之前按 `DATA.md` 取数。

> 想直接看结论 → 下一节 §0：三条问题的答案与数字都在那里。
> 想自己跑一遍 → §1 快速开始，再按 §2 判断你跑对了没有。

## 0. 值得关注的不是分数，是"分数可不可信"

关键结论都来自**可信度审计**，不是刷分：

- **同源泄漏会让分数虚高。** 溶解度上用随机划分，测试集里 31.01% 的序列与训练集有
  ≥25% 同一性；换成同源感知划分后降到 **0.00%**，分数掉下来 —— 掉下来的那部分才是虚高。
- **"更强的小头部"在小数据上没有收益。** 溶解度线上，MLP 与冻结嵌入线性探针的差距
  **6/6 次都不显著**（300M 上线性探针甚至更高）。ΔΔG 上有 40 万条数据，MLP 才转为正贡献。
- **规模收益有没有饱和，取决于数据量。** 这是两条线**结论相反**的地方（见下表）。
- **跨数据集仍然成立。** 溶解度模型拿到 DeepSoluE 的独立测试集上，无近亲子集里
  vs 长度基线**显著**、vs 线性探针**不显著** —— 与线内结论一致，不是自评自嗨。

### 两条线的核心对照（同源划分 / 官方划分，测试集）

| | 溶解度（test n=316） | ΔΔG（test n=56,344） |
|---|---|---|
| 训练条数 | 2,525 | 419,520 |
| 尺子（冻结嵌入线性探针） | 300M 0.6743 → 600M 0.6829 → 6B **0.7127** | — |
| 主模型（MLP + 手工特征） | 300M 0.6615 → 600M 0.7026 → 6B **0.7148** | — |
| 编码器规模 600M→6B | **不显著**（三配置 p=0.142 / 0.506 / 0.642） | **显著**（A 变体 +0.0316） |
| 一句话 | **规模收益在 600M 处已饱和** | **规模收益尚未饱和** |

> 差别来自**训练数据量**（2,525 vs 419,520）与**序列长度**（中位 ~310 aa vs ~54 aa），
> 不是编码器本身的问题。所以"6B 值不值得下"**没有普适答案**，要看你的数据量。

（ΔΔG 的完整结果见 `ddg/expected/key_metrics.csv`，溶解度见 `solubility/expected/`。）

## 2. ★★ 如何验证复现成功

**不要靠"跑完了没报错"判断成功。** 本仓库提供带**容差**的产物比对：

```bash
python tools/verify.py --line solubility --pred <你的产物目录>
python tools/verify.py --line ddg        --pred <你的产物目录>
```

它会逐条比对 `*/expected/key_metrics.csv` 里的锚点，输出：

```
[OK]   length_ridge            期望 0.3928  实得 0.3928  (容差 0.0000)
[OK]   esmc_ridge / 600M       期望 0.6829  实得 0.6831  (容差 0.0020)
[FAIL] mlp_hand / 6B           期望 0.7148  实得 0.6902  (容差 0.0080)  ← 差 0.0246
```

### 容差是分级的 —— 这是重点

不同锚点的可复现性**本来就不一样**，用一个容差去判是错的：

| 锚点类别 | 容差 | 为什么 |
|---|---|---|
| **与编码器无关的基线**（`length_ridge` / `aac_ridge` / `aac_rf`；ΔΔG 的 D 变体） | **0（必须逐位相同）** | 它们不看编码器，所以三档之间**必须完全相同**。这是**免费的管线正确性证据** —— 例如 `length_ridge` 三档都是 0.3928、ΔΔG 的 `D_hand` 三档都是 0.4710，一旦不同就说明数据或划分串了 |
| **数据派生的确定性量**（泄漏率、条数流水账、划分大小） | 0 | 纯计算，无随机性 |
| **冻结嵌入线性探针**（`esmc_ridge` / `esmc_hand_ridge`） | ±0.002 | 特征确定，但 ridge 求解有数值差异 |
| **训练出来的 MLP** | ±0.008 ~ ±0.010 | 依赖随机种子与 GPU 非确定性 |

> ⚠️ **绝对值对不上 ≠ 复现失败。** 先看**两类锚点**：
> ① 与编码器无关的基线是否**逐位相同**（不同 → 数据/划分问题，与模型无关）；
> ② 三档之间的**趋势**是否一致（如"6B 只显著优于 300M、与 600M 不显著"）。
> 趋势对了、绝对值在小范围内 → 属正常波动。趋势反了 → 才是真问题。

### 最省事的一条判据

跑完 `run_all.sh` 后，直接查这个卡点：

```text
homology 一行 test 的「>=25%」比例必须 ≈ 0
```

溶解度线在阶段 2 把这句打印成**显式卡点**（`run_all.sh` 里写着"⛔ 卡点"）。
**它是整条链的前提** —— 如果 homology 划分的 test 还有同源重叠，后面所有分数都不必看。

## 6. 不可改的口径（详见 `PROTOCOL.md`）

**复现失败最常见的原因不是代码报错，是口径漂移。** 以下几条改动后，数字就与已发表结果
不可比了 —— 每条都附了理由，请读完再决定改不改：

**溶解度线**
1. 主划分 = **homology**（同源感知），不是 random。random 会泄漏 31%。
2. 去冗余阈值 = **同一性 ≥25% 且覆盖 ≥50%**。
3. 主指标 = **Spearman**（不是 RMSE —— 同蛋白重复测量的组内极差中位达 37 个百分点，
   RMSE 存在无法突破的下限）。
4. 尺子 = **冻结嵌入线性探针**（`esmc_ridge`），任何新模型都要与它做**配对检验**。

**ΔΔG 线**
5. 标签 = **`−ddG_ML`**（**负号不能丢**，否则相关方向会反）。
6. 划分 = **官方 25% 聚类划分，按野生型蛋白**（保证同一蛋白的所有突变落在同一侧）。
7. 去泄漏范围 = 删 train / valid 的泄漏行，**test 不删**。
8. 核心交付 = **A − B**（`h_wt+h_mut` 减 `h_wt`），即"多算一个突变体表示值不值"。

**两线共有**
9. **判显著性只认配对检验**（`p = 2 × min(P(Δ≤0), P(Δ≥0))`）。
   ★ **绝不能拿两个独立 95% CI 是否重叠来判断** —— 同一批测试样本的误差是相关的。
   反例：300M 与 600M 的两个 `esmc_ridge` 预测彼此 Spearman 高达 **0.9576**，用独立 CI 判必然误判。
10. 零样本与训练后**分段读**（见 `PROTOCOL.md` §两线共有）。

## 7. 已知坑

`PITFALLS.md` 收了 14 条实测的**静默失败**（不报错、但结果错）：

- 文件写入被当成**覆盖式**（大小不变，`ls` 看不出）
- 镜像返回 **200 但 0 字节**
- 远端路径被 Git Bash **静默改写**
- **完成标记是假的**（崩了照样打印 `ALL_DONE`，本项目踩了三次）
- 事件顺序：**A 必须恰好等于 B 再拼第三块**（用 `np.array_equal` 断言，不是"看起来对"）
- 跨文件关联**不能用行号当键**（`index=False` 存过的 csv，行号无意义）
- 图变量名传错 → **静默产出两张同 md5 的图**
